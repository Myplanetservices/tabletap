## 3. Still Not Working (Could Not Fix in Demo Scope)

1. **Unseated Table Ordering Enforcement (`customer.js`)**:
   * *Reason:* In `initMenu()` in `customer.js`, when `isTrusted` is false, fallback logic automatically opens an open session and binds `localStorage.setItem('tqr_trusted_' + table.id, ...)`. As a result, guests who scan a raw table link without being seated by floor staff can bypass table key entry.
2. **Table Key Prompt & Slowdown Countdown (`customer.js`)**:
   * *Reason:* The `promptTableKey()` modal was defined but detached from the cart submission workflow. The required 4-attempt rate limiting and slowdown countdown timer are not implemented in vanilla JS.
3. **Unseated Waiter Call Prevention (`customer.js`)**:
   * *Reason:* Waiter calls only check a 30s/120s cooldown key in `localStorage` rather than verifying if the table status is `occupied`/seated.

## 4. Missing Features Found (NOT Built)

* **[Priority: High] Table Key Gatekeeper on Cart Submit:** Block placing orders until floor staff has seated the party, or require entering the 4-digit table key displayed on the table card.
* **[Priority: High] Brute-force Slowdown on Table Keys:** Introduce a client/server attempt counter that locks key entry for 60 seconds after 4 incorrect attempts.
* **[Priority: Medium] Staff Role Editing:** Allow owners to edit an existing staff member's role (Kitchen ↔ Floor) directly from `owner/staff.html` rather than requiring deletion and re-creation.
* **[Priority: Low] Dynamic Header Branding on Auxiliary Pages:** `menu/order-status.html` and `menu/bill.html` include hardcoded "The Olive Table" in the static HTML fallback before JS replaces it dynamically.

## 6. Real Backend Requirements (Cannot Work in Pure Static Demo)

1. **Hardware Serial Number & Device Authentication:** Web browsers cannot access hardware serials (IMEI/MAC). In production, device binding requires WebCrypto device keypairs stored in IndexedDB or a native wrapper.
2. **Real Transactional Email Delivery:** The current `dev/mailbox.html` runs through `mailer.js` and `localStorage`. Production requires an email service provider (e.g., Resend, Postmark, AWS SES, or SendGrid) with webhook delivery tracking.
3. **Cross-Device WebSockets / SSE Server:** Real-time sync across separate browser devices currently relies on `window.localStorage` storage events and broadcast channels. Production multi-device coordination requires a real WebSockets server or Server-Sent Events (SSE).
4. **Authoritative Geofencing & Anti-Spoofing:** Client-side GPS can be mocked in browser DevTools. Production requires backend IP/WiFi BSSID proximity validation.
5. **PCI-Compliant Payment Gateways:** Card payments in the demo simulate terminal taps. Production requires Stripe Terminal SDK or Square POS Web API with hardware readers.
